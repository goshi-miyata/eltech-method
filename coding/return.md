# returnは1箇所にする

---

## 1. ルール（要約）
- 処理の途中でメソッドを抜けてはいけない
- IF文は処理を実行するために使用し、途中で終了するために使用しない
- コードは上から下まで自然に読める構造とする
- 条件に応じた処理内容はコード上に明確に表現する
- 美しいコードとは可読性の高いコードである

---

## 2. 解説（原文）

### コーディングのお作法（その１：returnの考え方）

まず、下記のコードを見てください。

```java
  private int func(A)
  {
    if(A)
    {
      return = calc(1);
    }
    return = calc(2);
  }
```

ネットのサンプル含め、上記のようなコードがよく見受けられます。
これは、
    Aを判定し［真］であれば、exec(1)の戻り値を返し終了
    ［偽」だった場合は、exec(2)を返し終了
というコードです。

まず、このコードには２つの誤りがあります。

①処理の途中でメソッドを抜ける
    この例では、たったの５行ですから特に問題は起こらないと
    思うかもしれません。
    しかし、良識あるプログラマでは基本的には混乱します。
    まず、コードのIF文で何かを判定している事は理解できます。
    しかし、通常何かをする為に判定するのであって、
    途中でコードを抜ける為に判定するとは考えません。
    つまり、よく読まないとわからないコードとなっているわけです。
    
    先に記載したように、５行ですからすぐに理解できます。
    但し、こういったコードを書く方は、
    平気で１メソッドに50行／100行なんて各方です。
    そうすると、途中で処理を抜けるコードがあっても
    当然見落とす可能性があるわけです。
    基本的には、処理の途中で絶対にコードを抜けてはいけません。

②ストーリがない
    一体、このコードは何がしたいと思いますか？
        Aを判定し［真］であれば、exec(1)を
    ここまではよいと思います。
    しかし、上記のコードを日本語で表すとなんと表すとよいでしょう？
    私には出来ません。
    このコードに対しての機能はおそらく下記の通りです。
    引数(A)が[真]であれば、計算処理(1)を実行しその結果を
    引数(A)が[偽]であれば、計算処理(2)を実行しその結果を返す
    という機能でしょう。

    （ここで、計算処理に関しては、機能からはブラックボックスなので
    calc()メソッドを使うという記述は基本的にはないと考えてください。）
    
    では、この機能が投射された結果が上記のコードであっているでしょうか？
    答えは、ＮＧです。
    上記のコードは、引数(A)が[真]であれば・・・しか定義されておらず、
    先にも記載したように、あとの説明はコードから出来ません。
    偶然、機能の通りに動いているだけです。
    
では、正解のコードです。

```java
  private int func(A)
  {
    int ret;
    if(A)
    {
        ret = calc(1);
    }
    else
    {
        ret = calc(2);
    }
    return ret;
  }
```
  
これで、仕様通りです。
ここで注意点です。
先のコードが５行に対し、正解のコードは10行と倍になっています。
これまでも１メソッド25行以内というのを指示してきたと思います。
つまり、25行なんてコードは、可読性をよくすると
一瞬で終わってしまうのです。
その為にいろいろな工夫が必要になります。

美しいコードというのは、大前提として可読性の高いコードとなります。
