# if文とコメント

---

## 1. ルール（要約）
- コメントは可読性を損なわないように記述する
- コメントは分岐の前にまとめて記述する
- 分岐内で処理内容をコメントに依存させない
- コードは見た目とステップ数で理解できるようにする
- 美しいコードとは可読性の高いコードである

---

## 2. 解説（原文）

###コーディングのお作法（その４：if文のコメントはどこに書く？）

コーディングを行う際に常に考慮しなければならにのは可読性です。
可読性の確保は、見た目の可視性とステップ数です。

本件においては、この両方が加味されていなければなりません。
まず、下記の（悪い例）を見てください。

```java
    // Aが真の時は、○○を行います。
    if(A)
    {
        ○○；
    }
    // Aが偽の時は、○×を行います。
    else
    {
        ○×;
    }
```
    

これでは、正直何が書いてあるのか既にわかりません。
論外です。
次のコードは、


```java
    if(A)
    {
        // Aが真の時は、○○を行います。
        ○○；
    }
    else
    {
        // Aが偽の時は、○×を行います。
        ○×;
    }
```
    

今度は、分岐の中に処理の内容を記載しています。
最初に記載したコードよりはよいですが、
結局このコードもコメントがある為、
もしもそのコメントが長かったりする場合は、
とたんに可読性を落としてしまいます。

正解は

```java
    // Aが真の時は、○○を行います。
    // Aが偽の時は、○×を行います。
    if(A)
    {
        ○○；
    }
    else
    {
        ○×;
    }
```

となります。
そもそも、IF文自体、直感的にわかるように書かなければ
品質は保てません。
しかし、コメントを入れる事により、その可視性を落とす場合が多々あります。
何度も言いますが、コードは常にC2のカバレッジを確保する必要があります。
それを意識したコードでは、処理そのものが冗長になる事はありえません。
つまり、分岐１つが1つの単位でなければならず、
それのみがメソッドに存在しなければなりません。
そうすると、コメントに処理の内容を全て記載し、
あとはコードだけで事足ります。

また、コメントは本文中につけなくとも、
ヘッダコメントに記載されていれば、
本文中のコメントは一切なくとも構いません。


美しいコードというのは、大前提として可読性の高いコードとなります。
