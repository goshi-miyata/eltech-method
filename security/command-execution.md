# コマンド実行

---

## 参考ルール

- IDS07-J Runtime.exec()メソッドに渡す信頼できないデータは無害化する

---

## 1. ルール（要約）

- ユーザ入力をそのままOSコマンドへ渡してはいけない
- Runtime.exec()の使用には注意する
- 外部入力によりコマンドを組み立ててはいけない
- コマンド文字列を文字列連結で生成してはいけない
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その４：ユーザ入力でコマンドを実行しない）

システムによっては
OSコマンドを実行する場合があります。

例えば、

- ファイル圧縮
- バッチ起動
- 外部プログラム呼び出し

などです。

しかし、ここで外部入力を利用すると
重大な脆弱性につながる場合があります。

---

### 悪い例

```java
String command =
    "ping " + host;

Runtime.getRuntime().exec(command);
```

このコードは
ユーザ入力を利用して
コマンド文字列を生成しています。

一見問題ないように見えますが、
意図しないコマンドが実行される可能性があります。

---

### なぜ危険なのか

外部入力は信用できません。

利用者や攻撃者が
予期しない値を与える可能性があります。

その結果、

- 不正なコマンドの実行
- 情報漏えい
- システム破壊

につながる場合があります。

---

### 正しい例

```java
ProcessBuilder builder =
    new ProcessBuilder(
        "ping",
        host
    );
```

または、

```java
switch(type)
{
    case A:
        executeA();
        break;

    case B:
        executeB();
        break;
}
```

のように、
実行可能な処理をあらかじめ限定してください。

---

### 実行可能な処理を限定する

以下の考え方は危険です。

```java
String command =
    request.getParameter("command");
```

代わりに、

```text
実行可能な処理を事前定義する
```

という考え方を採用してください。

入力値によって
コマンドそのものを決定してはいけません。

---

### まとめ

外部入力を利用して
OSコマンドを組み立ててはいけません。

また、

- Runtime.exec()
- ProcessBuilder

を利用する場合も、
入力値の取り扱いには十分注意してください。

実行可能な処理は事前定義し、
利用者入力によってコマンド内容を変更しないようにしてください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
