# 例外処理

---

## 1. ルール（要約）

- 例外を握り潰してはいけない
- catchブロックを空にしてはいけない
- 例外発生時は原因を追跡可能にする
- 想定外の例外は適切に通知する
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その３：例外を握り潰さない）

例外はシステムからの異常通知です。

それを無視すると問題の発見が困難になります。

---

### 悪い例

```java
try
{
    process();
}
catch(Exception e)
{
}
```

一見問題なく動いているように見えます。

しかし実際は重大な障害が発生していても
誰も気付けません。

---

### 正しい例

```java
try
{
    process();
}
catch(Exception e)
{
    logger.error(
        "Process failed.",
        e
    );
    throw e;
}
```

少なくとも、

- ログ記録
- 呼び出し元通知

は行うべきです。

---

### 機密情報を漏洩しない

例外処理にはもう一つ注意点があります。

それは機密情報漏洩です。

---

### 悪い例

```java
return e.getMessage();
```

エラーメッセージによっては

- SQL文
- パス情報
- サーバ情報

が漏洩する場合があります。

---

### まとめ

例外は無視してはいけません。

異常は必ず記録し、
適切に呼び出し元へ通知してください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
