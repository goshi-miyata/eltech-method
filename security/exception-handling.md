# 例外処理

---

## 参考ルール

- ERR00-J チェック例外を抑制あるいは無視しない
- ERR01-J センシティブな情報を例外によって外部に漏えいしない

---

## 1. ルール（要約）

- 例外を握り潰してはいけない
- catchブロックを空にしてはいけない
- 例外発生時は原因を追跡可能にする
- センシティブな情報を例外に含めてはいけない
- 想定外の例外は適切に通知する
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その５：例外を握り潰さない）

例外はシステムからの異常通知です。

それを無視すると、

- 障害原因の特定
- ログ調査
- インシデント対応

が困難になります。

---

### 悪い例

```java
try
{
    process();
}
catch(Exception e)
{
}
```

一見問題なく動いているように見えます。

しかし、

- 何が起きたのか
- なぜ失敗したのか

を追跡できません。

---

### 正しい例

```java
try
{
    process();
}
catch(Exception e)
{
    logger.error(
        "Process failed.",
        e
    );
    throw e;
}
```

少なくとも、

- ログへの記録
- 呼び出し元への通知

は行うべきです。

例外を無視してはいけません。

---

### 機密情報を漏えいしない

例外処理にはもう一つ注意点があります。

それは情報漏えいです。

---

### 悪い例

```java
return e.getMessage();
```

例外メッセージには、

- SQL文
- ファイルパス
- 環境情報
- システム構成

などが含まれる場合があります。

そのまま外部へ返却すると、
攻撃者に有益な情報を与えてしまいます。

---

### 正しい例

```java
catch(Exception e)
{
    logger.error(
        "Process failed.",
        e
    );

    throw new ApplicationException(
        "処理中にエラーが発生しました。"
    );
}
```

利用者へは必要最小限の情報だけを通知します。

詳細な情報はログに出力し、
運用担当者が確認できるようにします。

---

### まとめ

例外を握り潰してはいけません。

また、

- SQL文
- パス情報
- 環境情報

などのセンシティブな情報を
例外経由で外部へ漏えいしてはいけません。

例外発生時は、

- 原因を記録する
- 呼び出し元へ通知する
- 利用者へ必要以上の情報を見せない

ことを徹底してください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
