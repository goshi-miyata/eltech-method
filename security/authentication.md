# 認証

---

## 1. ルール（要約）

- 認証処理を独自実装しない
- パスワードを平文で保存しない
- パスワードを平文で出力しない
- 強固なハッシュアルゴリズムを利用する
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その８：認証は慎重に扱う）

認証は

```text
その利用者が誰か
```

を確認する処理です。

システムの入口であり、
最も重要な機能の一つです。

---

### 悪い例

```java
if(password.equals(inputPassword))
{
    login();
}
```

パスワードを平文保存している可能性があります。

---

### 正しい例

```text
パスワード
↓
ハッシュ化
↓
比較
```

保存時も認証時も
ハッシュ値を利用してください。

---

### 自作しない

認証は非常に難しい分野です。

独自仕様を作るのではなく、

- Spring Security
- Keycloak
- 認証基盤

など実績ある仕組みを利用してください。

---

### まとめ

パスワードを平文で扱ってはいけません。

認証処理は実績のあるフレームワークを利用し、
独自実装を避けてください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
