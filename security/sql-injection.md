# SQLインジェクション対策

---

## 参考ルール

- IDS00-J SQLインジェクションを防ぐ

---

## 1. ルール（要約）

- SQLを文字列連結で組み立ててはいけない
- SQLは必ずプレースホルダを使用する
- ユーザ入力をSQL文へ直接埋め込まない
- 入力値検証とSQLインジェクション対策を混同してはいけない
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その２：SQL文字列連結禁止）

SQLインジェクションは代表的な脆弱性の一つです。

原因は単純です。

ユーザ入力を文字列連結して
SQL文を生成することです。

---

### 悪い例

```java
String sql =
    "SELECT * FROM USER WHERE USER_ID='"
    + userId
    + "'";
```

一見すると普通のコードに見えます。

しかし、ユーザ入力をそのまま
SQL文へ埋め込んでいます。

このようなコードでは、
攻撃者が意図的に細工した値を入力することで、
想定外のSQLが実行される可能性があります。

---

### 正しい例

```java
String sql =
    "SELECT * FROM USER WHERE USER_ID = ?";

PreparedStatement ps =
    conn.prepareStatement(sql);

ps.setString(1, userId);
```

プレースホルダを利用することで、

- SQL構造
- 入力データ

を分離できます。

SQL文の組み立てと
データの受け渡しを分離することが重要です。

---

### 入力値検証だけでは防げない

以下の考え方は誤りです。

```text
入力値をチェックしているから安全
```

入力値検証は必要です。

しかし、

- 入力値検証
- SQLインジェクション対策

は別の問題です。

入力値検証を実施していても、
SQLを文字列連結していれば
SQLインジェクションの危険性は残ります。

そのため、
SQL生成時には必ずプレースホルダを使用してください。

---

### まとめ

SQLを文字列連結してはいけません。

ユーザ入力はSQL文へ埋め込まず、
プレースホルダを使用して渡してください。

また、

- 入力値検証
- SQLインジェクション対策

は別であることを理解し、
両方を実施するようにしてください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
