# SQLインジェクション

---

## 1. ルール（要約）

- SQLを文字列連結で組み立ててはいけない
- SQLは必ずプレースホルダを使用する
- ユーザ入力をSQL文へ直接埋め込まない
- 入力値検証とSQLインジェクション対策は別である
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その２：SQL文字列連結禁止）

SQLインジェクションは最も有名な脆弱性の一つです。

原因は非常に単純です。

ユーザ入力を文字列連結してSQLを生成することです。

---

### 悪い例

```java
String sql =
    "SELECT * FROM USER WHERE USER_ID='"
    + userId
    + "'";
```

もし userId に悪意ある値が入力された場合、
意図しないSQLが実行される可能性があります。

---

### 正しい例

```java
String sql =
    "SELECT * FROM USER WHERE USER_ID = ?";

PreparedStatement ps =
    conn.prepareStatement(sql);

ps.setString(1, userId);
```

プレースホルダを利用することで、
SQL構造とデータを分離できます。

---

### 入力チェックだけでは防げない

以下の考え方は誤りです。

```text
入力値をチェックしているから安全
```

入力検証は必要です。

しかし、

- 入力検証
- SQLインジェクション対策

は別物です。

必ずプレースホルダを利用してください。

---

### まとめ

SQLを文字列連結してはいけません。

SQL生成時は必ずプレースホルダを使用し、
ユーザ入力はパラメータとして渡してください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
