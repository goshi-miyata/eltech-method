# 機密情報管理

---

## 1. ルール（要約）

- パスワードをコードへ埋め込まない
- APIキーをコードへ埋め込まない
- 接続情報をソースコードへ記載しない
- 機密情報は設定ファイルまたは環境変数で管理する
- 美しいコードとは安全で可読性の高いコードである

---

## 2. 解説

### セキュアコーディングのお作法（その５：秘密はコードに書かない）

ソースコード管理システムには
多くの人がアクセスできます。

そのため、
機密情報を直接記載してはいけません。

---

### 悪い例

```java
private static final String PASSWORD =
    "password123";

private static final String API_KEY =
    "xxxxxxxx";
```

このコードがGitへ登録されると、
長期間残り続けます。

---

### 正しい例

```java
String password =
    System.getenv("DB_PASSWORD");
```

環境変数や設定ファイルから
取得してください。

---

### なぜ危険なのか

流出した場合、

- DB接続
- 外部サービス
- クラウド環境

へ不正アクセスされる可能性があります。

---

### まとめ

機密情報はコードへ記載してはいけません。

機密情報は設定として管理し、
ソースコードと分離してください。

美しいコードとは、
安全で可読性の高いコードであると考えます。
