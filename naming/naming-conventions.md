# 命名規則～変数名とコメント

---

## 1. ルール（要約）
- 変数名やメソッド名は内容が理解できる名前とする
- 抽象的な名前は使用せず、意味が明確になる名前を付ける
- 抽象的な処理の場合はパラメータにより意味を補う
- 略称は使用しない
- コメントは必要最小限とし、コードから内容が理解できるようにする
- 美しいコードとは可読性の高いコードである

---

## 2. 解説（原文）

### コーディングのお作法（その５：変数名とコメント）

変数名（クラス名等含む）はとても重要です。

では、NGワードから
```java
    GetData()
```
読んで字の如く、データを取得するという事は判ります。
しかし、この変数名からは、何のデータを取得するのか
さっぱりわかりません。
みなさん、何のデータを取得する為のメソッドかわかりますか？
わかるわけありません。
よって、書いてはいけないコードとなります。
では、どうすればよいのでしょうか？
```java
    GetGdp2009FromJapan()
```
であれば、どうでしょう。
    GDP : 国内総生産
です。
英訳できるかどうかは別にして、このメソッド名から
    日本の2009年の経済成長率を取得する
という事が判ります。

変数名にしても、クラス名にしても常に読んでわかる名前を
意識しなければなりません。
    
では、GetData()が本当にいけないのか？
そうではありません。
もう一度、GetData()がNGだった理由を考えてください。
理由は、名前から何をする為のメソッドかわからないという事でした。
つまり、抽象的な名前だから駄目なわけです。

では、抽象的な処理を行うメソッドであればどうでしょう。
例えば、
```java
    GetData("GDP", "Japan", 2009")
```
というメソッドにしてみました。
すると、
    日本の2009年の経済成長率を取得する
という事が判り、また、GetDataは他にもパラメータを変更する事により
いろいろな動作を可能とする、抽象的なメソッドである事が判ります。

このように、名前とは考えてつけなければなりません。

次に、名前の付け方です。
基本的には、略称は禁止です。

上記の例でいうとGDPはどうかという話になりますが、
GDPはそれ自体が単語として成立している為、問題ではありません。
では、どういった場面でしょうか。
```java
    CDate
    UDate
```
この二つなにかわかりますか？
答えは
    CDate：CreateDate
    UDate：UpdateDate
です。
残念ながら、このようなコードを記載する技術者は山ほどいます。
おそらく、書いた本人も後にこのコードを見た場合、
前後を解析しなければ、わからなくなっているでしょう。

私は、こういったコードを書く事は恥ずべき事だと考えています。
また、プロとしては失格だとも思います。
資格制であれば、こういった方は資格剥奪もすべきだとも考えます。

なぜ、このような強固な事を言うかわかりますか？
それは、プログラムは人の為に書くものであり、
人が読めないコードは書くべきではないからです。

---
次にコメントです。
コメントは必須です。
コメントには、ヘッダコメントもあればコード中の注釈的なコメントもあります。
では、どの程度必要でしょうか？

まず、最悪なコードは下記のコードです。
```java
    CDate       //  生成時間
    UDate       //  更新時間
```
そもそも、変数名で不正な記述をしており、さらに輪をかけるように
変数名を説明するコメントまで付加されてしまいます。
このコード実際にかくと、２行のコメントを記載するのに、
10秒かかりました。
皆さん、わかっていますか？
この10秒にも単価がかかっているのですよ！！

まず、ルールとして、
コメントは出来るだけ記載しない事を目標としてください。
では、記載しないという事はどういうことでしょうか？
これは、コードを読む事により、内容が理解できるようにする
という事です。
例えば、
```java
    //  ユーザ情報データセットのインスタンスを生成します。
    UserInfoDataSet ds = new UserInfoDataSet(); 
```
というコード、如何に無駄な事をしているかわかりますか？
このコメントを記載する事により、可読性も悪くし、工数も掛かり
最終的には、品質も悪くします。
もしも、私がユーザであれば、金返せと言うでしょう。

コメントは、ヘッダコメントにそのメソッドの機能を記載すれば、
本文中には皆無でも構わないと考えています。

変数名やコメント１つで、生産性や品質に影響します。
常にわかりやすいコードとは何かを意識して開発をしてください。


美しいコードというのは、大前提として可読性の高いコードとなります。
